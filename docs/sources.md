## Iteration 2 Sources

### Primary sources read in full (verified, not just abstract/snippet)
190. **Zambianco, Facchinetti, Siracusa (2025)** — full text read via arXiv HTML. Confirms exact method (Multi-Terminal Vertex Separator ILP, solved with SCIP), exact eval setup (100 random instances, 1–9 attack targets, 266 ATT&CK Enterprise techniques, 153 eligible outcome-targets), and exact results (runtime 0.042–0.060s; 4 decoys optimal vs. 40 decoys for "Group" baseline at 1 target). 🟢 https://arxiv.org/html/2404.12783
191. **Zambianco, Facchinetti, Doriguzzi-Corin, Siracusa (2024)** — full text read via arXiv PDF. Confirms exact method (non-linear integer program + greedy heuristic via betweenness centrality), exact eval setup (M=100–500 microservices, N up to 20 nodes, Barabási–Albert graphs, Alibaba cloud trace dataset, Apple M1 Pro 14-core/16GB, 100 configs, 95% CI), exact results (decoy-to-microservice ratio 21.5%→14.3% as M grows; optimal hits 80% interception at δ=0.5 vs. sidecar needing ~160% of resources). 🟢 https://arxiv.org/pdf/2303.03151
192. **Park & Dagher, "Adaptive Honeypot Allocation in Multi-Attacker Networks via Bayesian Stackelberg Games"** — full text read via arXiv HTML. **CORRECTION to iteration-1 note:** this paper has NO reference to the Purdue Model, IEC 62443, or any OT/ICS concept anywhere in intro/related-work/system-model. The "layered structure" is generic graph-distance layering (nodes grouped by shortest-path distance to target, value discounted by α^distance) used purely for MIP tractability via backward induction — not an industrial reference architecture. Scales to 500 nodes / 1,500+ edges. Venue not confirmed as Computers & Security in the text read — treat as arXiv:2505.16043 until verified. 🟢 https://arxiv.org/html/2505.16043

## Full-Text Verification — Devika Jay, confirmed from the primary source

312. **Devika Jay (2023) — full text now read.** ⭐⭐⭐ Confirms and sharpens the distinction drawn from the abstract alone. The paper solves a **graph-observability problem, not a site-selection problem**: the GOOSE VLAN is a strongly-connected bidirectional graph, provably unobservable by a single decoy (any digraph needs out-degree ≤1 at every vertex to be observable, and this one doesn't). The core contribution is decomposing that graph into P(n) = 2 + n(n−3)/2 minimal **"observable subgraphs"** — two cyclic rings (clockwise/counter-clockwise GOOSE flow) plus per-node inward/outward star subgraphs — that together guarantee **full** observability with far fewer decoys than covering every individual path would need (2 vs. 6 decoys for a 3-IED VLAN; 56 vs. 132 for the 12-IED PSRC-I5 test case). The bi-level Stackelberg game then allocates *protection-vs-detection decoy type* across those already-determined subgraph slots — it does not choose *which* assets receive a decoy from a larger candidate pool the way this project's problem does. The reward functions are built entirely from GOOSE/substation-specific cyber-physical dynamics — Cruz's network-calculus delay bounds (arrival/service curves) and a voltage-state residual for a false-trip scenario — protocol-specific machinery with no IEC 62443, no MITRE ATT&CK, no asset criticality, and no multi-asset attack-path modeling anywhere in it. **Directly citable:** the paper's own conclusion states extending from the GOOSE VLAN to the SV VLAN — a second VLAN *within the same substation* — is still future work, and real-testbed deployment is still future work too. That is the authors' own words confirming the scope boundary, not an inference. 🟢 (full text on file)

**Net effect: this closes the Jay thread. The full text makes the project's differentiation from it stronger and easier to state than the abstract-only version did — this is a resource-allocation-under-guaranteed-full-observability problem on one VLAN's message graph, not a budget-constrained, multi-metric, attack-path-driven site-selection problem across a multi-zone OT architecture. No further chasing of this paper is needed.**
